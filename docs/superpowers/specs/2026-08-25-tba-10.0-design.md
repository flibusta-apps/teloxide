# Telegram Bot API 10.0 Support Design

## Goal

Raise teloxide support from Telegram Bot API 9.6 to **10.0** (announced May 8,
2026), covering every type, field, update, and method introduced in that
release. Changes from Bot API 10.1 through 10.3 are explicitly out of scope.

## Source of truth

The implementation must use the archived Telegram Bot API reference captured
on May 15, 2026. This snapshot contains Bot API 10.0 and predates later 10.x
releases, avoiding accidental implementation of newer API surface.

## Approach

Follow teloxide's existing API-bump process:

1. Maintain Bot API object models manually under `crates/teloxide-core/src/types/`.
2. Maintain method metadata manually in `crates/teloxide-core/schema.ron`.
3. Regenerate request payloads, requester methods, forwarding macros, and
   payload-module exports through the repository's code-generation test path.
4. Refresh `custom_v2.json` from the corresponding tba-parser schema so type
   consistency checks cover the same API revision.
5. Integrate new update kinds into the high-level dispatching/filter surface in
   the same way existing message-based updates are integrated.

This preserves the repository's established source-of-truth boundaries:
`schema.ron` covers methods only, while Rust type modules cover API objects and
unions.

## API surface

### Guest mode

Add:

- `User::supports_guest_queries`.
- `Message::{guest_query_id, guest_bot_caller_user, guest_bot_caller_chat}`.
- `Update::guest_message` and its matching `UpdateKind`/filter/dispatcher
  integration.
- `SentGuestMessage` with `inline_message_id`.
- `answer_guest_query(guest_query_id, result) -> SentGuestMessage`.

The new update must be treated as a message-bearing update everywhere that
existing update variants are exhaustively matched. It must not replace or alter
the behavior of ordinary `message` updates.

### Chat management

Add `can_react_to_messages` to both `ChatMemberRestricted` and
`ChatPermissions`. In `ChatPermissions`, absence must deserialize as `None`,
consistent with its optional API field.

Extend `get_chat_administrators` with optional `return_bots`.

Add these methods, retaining Telegram's two independently optional actor
selectors:

- `delete_message_reaction(chat_id, message_id, user_id?, actor_chat_id?) -> True`
- `delete_all_message_reactions(chat_id, user_id?, actor_chat_id?) -> True`

### Poll media

Add the object and input-media types:

- `PollMedia`, an untagged/one-of media object with animation, audio, document,
  live-photo, location, photo, sticker, venue, and video variants.
- `InputMediaSticker`, `InputMediaLocation`, and `InputMediaVenue`.
- Input unions `InputPollMedia` and `InputPollOptionMedia`.

Extend current poll models:

- `PollOption::media: Option<PollMedia>`.
- `InputPollOption::media: Option<InputPollOptionMedia>`.
- `Poll::{members_only, country_codes, explanation_media, media}`.

Extend `send_poll` with `members_only`, `country_codes`, `explanation_media`,
and `media`, preserving the official parameter order in `schema.ron`. Update
the documented/validated option count from 2--12 to 1--12 where teloxide
enforces or describes that constraint.

`InputMediaSticker`, `InputMediaLocation`, and `InputMediaVenue` are not
members of the general `InputMedia` union. They belong only to the applicable
poll-media input unions.

### Live photos

Add:

- `LivePhoto`.
- `InputMediaLivePhoto`.
- `PaidMediaLivePhoto` and `InputPaidMediaLivePhoto`.
- `Message::live_photo` and `ExternalReplyInfo::live_photo`.
- The live-photo variants in the existing general input-media and paid-media
  unions where the Bot API permits them.
- `send_live_photo`, with required recipient, live-photo video, and static
  photo; and the established optional caption, message-routing, delivery,
  reply, and markup parameters.

`send_media_group` and `edit_message_media` must accept live-photo input by
way of the existing general input-media union. Their documentation should
describe the newly supported media form if generated documentation is sourced
from `schema.ron`.

### Managed bots and personal chats

Add `BotAccessSettings` and methods:

- `get_managed_bot_access_settings(user_id) -> BotAccessSettings`
- `set_managed_bot_access_settings(user_id, is_access_restricted,
  added_user_ids?) -> True`
- `get_user_personal_chat_messages(user_id, limit) -> Vec<Message>`

## Generated request layer

`schema.ron` will declare the seven new methods and the two amended methods:

- `answerGuestQuery`
- `getManagedBotAccessSettings`
- `setManagedBotAccessSettings`
- `getUserPersonalChatMessages`
- `deleteAllMessageReactions`
- `deleteMessageReaction`
- `sendLivePhoto`
- amended `getChatAdministrators`
- amended `sendPoll`

Its API version declaration becomes `10.0` with announcement date `May 8,
2026`. Generated artifacts include payload files, the payload module index,
`Requester` methods, and forwarding macros. Generated files are not manually
edited unless compilation exposes an established non-generated integration
point.

## Documentation and compatibility

Update both crate-level supported-version notices, both API-coverage badges,
and the root/core changelogs. The root changelog receives a concise 10.0
support entry; the core changelog enumerates the new capabilities by area.

Bot API 10.0 is additive for teloxide consumers. No migration-guide entry or
breaking-change marker is expected. The relaxed poll option lower bound is a
compatibility expansion, not a breaking change.

## Verification

The primary release evidence is `just test`, which runs code generation and
the project's full configured test path. It must leave generated files
up-to-date and all checks green.

Focused tests will establish the new public behavior before implementation:

- deserialize representative Telegram JSON for guest messages, live photos,
  poll media, access settings, and added optional fields;
- serialize requests for each new method and both amended methods, including
  optional fields and input-file handling for `send_live_photo`;
- compile the relevant high-level update filters/dispatchers with a
  `guest_message` update;
- confirm live photos are accepted in existing general media and paid-media
  unions, while sticker/location/venue inputs are accepted only in poll-media
  unions.

The full test path is the final integration gate; no live Telegram API calls
are required or planned.

## Non-goals

- Bot API 10.1, 10.2, and 10.3 changes.
- Unrelated refactors of media, polling, or dispatching APIs.
- New runtime feature flags, dependencies, or network integration tests.
