# Telegram Bot API 10.1 Implementation Specification — Join Request Queries & Polls

**Reference Date**: June 11, 2026 (TBA 10.1 release)
**Archive Snapshot**: https://web.archive.org/web/20260613201709/https://core.telegram.org/bots/api
**Date Range Validation**: Between June 11, 2026 (TBA 10.1 release) and July 14, 2026 (TBA 10.2 release)

## Feature Area 1: Join Request Queries

Bot API 10.1 introduces support for processing chat join requests through specialized query handlers.

### 1.1 User.supports_join_request_queries

**Anchor**: https://core.telegram.org/bots/api#user

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `supports_join_request_queries` | Boolean | Optional | `True`, if the bot supports join request queries and can be assigned to process them. Returned only in `getMe`. |

### 1.2 ChatFullInfo.guard_bot

**Anchor**: https://core.telegram.org/bots/api#chatfullinfo

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `guard_bot` | User | Optional | The bot that processes join request queries in the chat. The field is only available to chat administrators. |

### 1.3 ChatJoinRequest.query_id

**Anchor**: https://core.telegram.org/bots/api#chatjoinrequest

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `query_id` | String | Optional | Identifier of the join request query. If present, the bot must call `sendChatJoinRequestWebApp` or directly call `answerChatJoinRequestQuery` within 10 seconds. |

### 1.4 Method: answerChatJoinRequestQuery

**Anchor**: https://core.telegram.org/bots/api#answerchatjoinrequestquery

Use this method to process a received chat join request query. Returns True on success.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `chat_join_request_query_id` | String | Yes | Unique identifier of the join request query |
| `result` | String | Yes | Result of the query. Must be `"approve"`, `"decline"`, or `"queue"` (leave the decision to other administrators). |

**Return Type**: True

### 1.5 Method: sendChatJoinRequestWebApp

**Anchor**: https://core.telegram.org/bots/api#sendchatjoinrequestwebapp

Use this method to process a received chat join request query by showing a Mini App to the user before deciding the outcome. Returns True on success.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `chat_join_request_query_id` | String | Yes | Unique identifier of the join request query |
| `web_app_url` | String | Yes | The HTTPS URL of the Mini App to be opened |

**Return Type**: True

## Feature Area 2: Polls

### 2.1 Class: Link

**Anchor**: https://core.telegram.org/bots/api#link — Represents an HTTP link.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `url` | String | Yes | URL of the link |

### 2.2 Class: InputMediaLink

**Anchor**: https://core.telegram.org/bots/api#inputmedialink — Represents an HTTP link to be sent.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | String | Yes | Type of the media, must be `link` |
| `url` | String | Yes | HTTP URL of the link to be sent |

**Compatibility**: `InputMediaLink` is valid as `InputPollOptionMedia` but NOT as `InputPollMedia` (poll description/explanation media) — mirrors how sticker media is poll-option-only per the 10.0 design.

### 2.3 PollMedia.link

**Anchor**: https://core.telegram.org/bots/api#pollmedia

`PollMedia` is the existing flat, untagged-by-presence struct (`crates/teloxide-core/src/types/poll_media.rs`) with one-of-N optional fields (no `type` discriminator — determined by which optional field is set). TBA 10.1 adds one more optional field, in this definition order relative to the others: `animation, audio, document, link, live_photo, location, photo, sticker, venue, video`.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `link` | Link | Optional | The HTTP link attached to the poll option |

## Summary of Changes

- `User` — add `supports_join_request_queries: Option<bool>`
- `ChatFullInfo` — add `guard_bot: Option<User>`
- `ChatJoinRequest` — add `query_id: Option<String>`
- New type `Link { url: String }`
- New type `InputMediaLink { type: "link", url: String }` (as an `InputPollOptionMedia` variant only, not general `InputMedia` and not `InputPollMedia`)
- `PollMedia` — add `link: Option<Link>` field (insert alphabetically between `document` and `live_photo`)
- New method `answerChatJoinRequestQuery(chat_join_request_query_id, result) -> True`
- New method `sendChatJoinRequestWebApp(chat_join_request_query_id, web_app_url) -> True`

**End of Specification**
