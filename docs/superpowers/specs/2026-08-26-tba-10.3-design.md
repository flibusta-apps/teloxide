# Telegram Bot API 10.3 support

## Goal

Upgrade `teloxide-core` from Bot API 10.2 to 10.3 (released 2026-08-24), keeping the generated public Rust API, checker metadata, and user documentation in sync with Telegram's official API reference and changelog.

## Source of truth

Telegram's official Bot API changelog and reference are authoritative. The project-local checker metadata (`custom_v2.json`) and method schema (`schema.ron`) are the inputs to the existing generation and schema-check workflow.

## Design

Update the checker metadata and generated API for these 10.3 surfaces:

- Rich messages: eight new button, quotation, and document types; `is_compact` table fields; document upload-link support.
- Ephemeral messages: `EphemeralMessageParameters`; the replacement of `receiver_user_id` and `callback_query_id` on the affected send methods; additional rich-message, caption, and text parameters.
- Permissions: `can_send_welcome_messages` on administrator types and `promoteChatMember`.
- Reply markup: `DisabledButton`, disabled inline buttons, and `force_reply` fields.
- Message generation: `can_stop`, `keep_on_stop`, `MessageGenerationStopped`, and `Update.stopped_message_generation`.
- Communities and gifts: `CommunityChatJoined`, `Message.community_chat_joined`, and `UniqueGiftInfo` text, entities, and privacy fields.

Set `editEphemeralMessageMedia` to use multipart encoding so an `InputMedia` value can reference a new `attach://...` upload.

Set the RON API version to 10.3 with the official release date. Regenerate the payload, requester, type, and checker-test outputs using the repository's established workflow. Synchronize API-version badges, crate-level documentation, changelogs, and migration guidance. The parameter replacement for ephemeral-message sends is documented as a breaking public API change.

## Validation

Validation must demonstrate that checker metadata, `schema.ron`, and the Rust API agree, and that multipart file upload remains enabled for `editEphemeralMessageMedia`. Run the documented generation/schema-check workflow, affected `teloxide-core` tests, workspace checks/tests, and formatting. Generated exhaustive tests must cover all new and changed Bot API surface.
