## Rich Message Formatting Options

### Overview

Rich messages support advanced structured formatting options like headings, lists, tables, media, block quotations, collapsible blocks, footnotes, and formulas. Telegram clients render them accordingly. Rich message content can be specified using Markdown-style or HTML-style formatting.

Plain URLs, e-mail addresses, username mentions, hashtags, cashtags, bot commands, phone numbers, and bank card numbers are detected automatically. To disable automatic entity detection, pass `True` in the `skip_entity_detection` field.

### Rich Message Limits

Rich messages are subject to the following limits:

- Up to **32768 UTF-8 characters** in the rich message text, including custom emoji alternative text and formula source.
- Up to **500 blocks**, including nested blocks, list items, ordered list items, table rows, quotation blocks, and details blocks.
- Up to **16 levels** of nested formatting and blocks.
- Up to **50 media attachments** in total, including photos, videos, and audio files.
- Up to **20 columns** in a table.

(Markdown/HTML syntax tables omitted here for brevity — not needed for Rust type modeling. See archive snapshot for full syntax reference if documentation prose needs it.)

**Important Notes (both Markdown and HTML style):**

- Rich Markdown is compatible with GitHub Flavored Markdown where possible and can contain arbitrary HTML.
- Media can be specified only as a separate block. Media blocks support only HTTP and HTTPS URLs.
- Table cells can contain only inline formatting.
- Formula source is treated as raw LaTeX.

## InputRichMessage Object

**Anchor:** https://core.telegram.org/bots/api#inputrichmessage

Describes a rich message to be sent. Exactly **one** of the fields `html` or `markdown` must be used.

| Field | Type | Description |
|-------|------|-------------|
| `html` | String | *Optional*. Content of the rich message to send described using HTML formatting. |
| `markdown` | String | *Optional*. Content of the rich message to send described using Markdown formatting. |
| `is_rtl` | Boolean | *Optional*. Pass `True` if the rich message must be shown right-to-left |
| `skip_entity_detection` | Boolean | *Optional*. Pass `True` to skip automatic detection of entities (e.g., URLs, email addresses, username mentions, hashtags, cashtags, bot commands, or phone numbers) in the text |

## RichBlock Types

The `RichBlock` object represents a block in a rich formatted message. It is always an object (not String/Array like RichText) and can be any of the following types:

**Anchor:** https://core.telegram.org/bots/api#richblock

### RichBlockCaption (supporting sub-object, no `type` tag)
**Anchor:** https://core.telegram.org/bots/api#richblockcaption — Caption of a rich formatted block.
| Field | Type | Description |
|-------|------|-------------|
| `text` | [RichText](#richtext-types) | Block caption |
| `credit` | [RichText](#richtext-types) | *Optional*. Block credit, corresponds to HTML `<cite>` |

### RichBlockTableCell (supporting sub-object, no `type` tag)
**Anchor:** https://core.telegram.org/bots/api#richblocktablecell — Cell in a table.
| Field | Type | Description |
|-------|------|-------------|
| `text` | [RichText](#richtext-types) | *Optional*. Text in the cell. If omitted, the cell is invisible. |
| `is_header` | True | *Optional*. `True` if the cell is a header cell |
| `colspan` | Integer | *Optional*. Number of columns the cell spans if > 1 |
| `rowspan` | Integer | *Optional*. Number of rows the cell spans if > 1 |
| `align` | String | Horizontal alignment: one of `"left"`, `"center"`, `"right"` |
| `valign` | String | Vertical alignment: one of `"top"`, `"middle"`, `"bottom"` |

### RichBlockListItem (supporting sub-object, no `type` tag)
**Anchor:** https://core.telegram.org/bots/api#richblocklistitem — An item of a list.
| Field | Type | Description |
|-------|------|-------------|
| `label` | String | Label of the item |
| `blocks` | Array of [RichBlock](#richblock-types) | The content of the item |
| `has_checkbox` | True | *Optional*. `True` if the item has a checkbox |
| `is_checked` | True | *Optional*. `True` if the item has a checked checkbox |
| `value` | Integer | *Optional*. For ordered lists, numeric value of the item label |
| `type` | String | *Optional*. For ordered lists, type of item label: `"a"`, `"A"`, `"i"`, `"I"`, or `"1"` |

> Note: `RichBlockListItem.type` is an unrelated optional string field (ordered-list label style), NOT a serde discriminator tag. Do not confuse with the `RichBlock`/`RichText` `type` tag fields.

## API Methods

### sendRichMessage
**Anchor:** https://core.telegram.org/bots/api#sendrichmessage

Use this method to send rich messages. If the message contains a block with a media element, the bot must have the right to send that media to the chat. On success, the sent Message is returned.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `business_connection_id` | String | Optional | Unique identifier of the business connection on behalf of which the message will be sent |
| `chat_id` | Integer or String | Yes | Target chat id or `@username` |
| `message_thread_id` | Integer | Optional | Target message thread (topic) of a forum |
| `direct_messages_topic_id` | Integer | Optional | Identifier of the direct messages topic; required if sent to a direct messages chat |
| `rich_message` | InputRichMessage | Yes | The message to be sent |
| `disable_notification` | Boolean | Optional | Send silently |
| `protect_content` | Boolean | Optional | Protect contents from forwarding/saving |
| `allow_paid_broadcast` | Boolean | Optional | Pass True to allow up to 1000 messages/sec for a fee |
| `message_effect_id` | String | Optional | Message effect id; private chats only |
| `suggested_post_parameters` | SuggestedPostParameters | Optional | Suggested post parameters; direct messages chats only |
| `reply_parameters` | ReplyParameters | Optional | Description of the message to reply to |
| `reply_markup` | InlineKeyboardMarkup or ReplyKeyboardMarkup or ReplyKeyboardRemove or ForceReply | Optional | Additional interface options |

**Returns:** Message

### sendRichMessageDraft
**Anchor:** https://core.telegram.org/bots/api#sendrichmessagedraft

Use this method to stream a partial rich message to a user while the message is being generated. The streamed draft is ephemeral (30-second preview) — once finalized, `sendRichMessage` must be called with the complete message to persist it.

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `chat_id` | Integer | Yes | Target private chat id |
| `message_thread_id` | Integer | Optional | Target message thread |
| `draft_id` | Integer | Yes | Unique identifier of the message draft; must be non-zero. Same-id changes are animated. |
| `rich_message` | InputRichMessage | Yes | The partial message to be streamed |

**Returns:** Boolean (True on success)

### editMessageText
**Anchor:** https://core.telegram.org/bots/api#editmessagetext

| Parameter | Type | Required | Description |

## Nested / Recursive Structure Notes

1. **RichText recursion**: `RichText` fields within formatting objects (Bold, Italic, DateTime, TextMention, Url, EmailAddress, PhoneNumber, BankCardNumber, Mention, Hashtag, Cashtag, BotCommand, AnchorLink, Reference, ReferenceLink) contain other `RichText` values, enabling nested formatting (e.g. bold italic text). `RichTextAnchor` and `RichTextMathematicalExpression`/`RichTextCustomEmoji` do NOT have a `text` field (leaf-only: `name`/`expression`/`custom_emoji_id`).
2. **RichBlock recursion**:
   - `RichBlockList.items` → `RichBlockListItem[]`
   - `RichBlockListItem.blocks` → `RichBlock[]` (nested blocks within list items)
   - `RichBlockBlockQuotation.blocks` → `RichBlock[]`
   - `RichBlockCollage.blocks` / `RichBlockSlideshow.blocks` → `RichBlock[]` (media blocks)
   - `RichBlockDetails.blocks` → `RichBlock[]`
3. **Table structure**: `RichBlockTable.cells` is `Array of Array of RichBlockTableCell` (rows of columns); cell text is inline `RichText` only (not enforced by the type system, just documented behavior).
4. **Media blocks** reference existing API object types: `PhotoSize`, `Video`, `Animation`, `Audio`, `Voice`, `Location` — all already implemented in teloxide-core.
