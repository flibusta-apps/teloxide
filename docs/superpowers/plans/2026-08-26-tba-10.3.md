# Telegram Bot API 10.3 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add complete, type-safe Telegram Bot API 10.3 support to teloxide-core, including its breaking ephemeral-message API update.

**Architecture:** Hand-maintained Rust object models remain under `crates/teloxide-core/src/types`; `schema.ron` declares the request API and generates payload/requester code. Telegram's official 2026-08-24 Bot API reference is the source of truth; a tba-parser-generated checker schema and schema-check tests enforce that the generated and hand-written API agree.

**Tech Stack:** Rust, serde, serde_with, schemars test support, cargo test code generation, tba-parser schema.

---

## File structure

| Area | Files | Responsibility |
| --- | --- | --- |
| Checker baseline | `schema.ron`, `custom_v2.json`, `codegen/schema_check/*` | Declare 10.3 and mechanically check the Rust API against its schema. |
| Rich messages | `types/{rich_text,rich_block,input_rich_block}.rs` | Add button, expandable quotation, document block, compact-table models, and input file traversal. |
| Core models | `types/{ephemeral_message_parameters,disabled_button,message_generation_stopped,community_chat_joined}.rs`, their parents, `types.rs` | New standalone objects and all amended existing object fields. |
| Requests | `schema.ron`, generated `payloads/*.rs`, `payloads.rs`, `requests/requester.rs`, `bot/api.rs` | Replace ephemeral routing parameters, add 10.3 method fields, and enable multipart media editing. |
| Integration | requester forwarding/adaptors and `handler_ext.rs` | Keep every requester adaptor and update dispatcher aligned with changed generated API. |
| Release documents | READMEs, crate docs, changelogs, migration guide | Announce 10.3 and document the public breaking parameter replacement. |
