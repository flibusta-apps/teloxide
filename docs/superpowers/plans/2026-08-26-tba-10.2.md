# Telegram Bot API 10.2 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add complete, type-safe Telegram Bot API 10.2 support to teloxide without including Bot API 10.3 changes.

**Architecture:** Hand-maintained Rust models live in `teloxide-core/src/types`; `schema.ron` remains the method metadata source and regenerates payload/requester sources. New input rich blocks follow the existing tagged `RichBlock`/`InputMedia` model, while response-only fields are additive optional fields in their existing parent types.

**Tech Stack:** Rust, serde, serde_with, schemars test support, cargo code generation, tba-parser schema.

---

## File structure

| Area | Files | Responsibility |
| --- | --- | --- |
| Input rich messages | `types/input_rich_block.rs` (new), `types/input_rich_message_media.rs` (new), `types/rich_message.rs`, `types/input_media.rs`, `types.rs` | Tagged input blocks, input media references, voice-note media, and exports. |
| Response models | `types/{bot_command,message,reply_parameters,chat_full_info,update}.rs`, `types/{community,community_chat_added,community_chat_removed,bot_subscription_updated}.rs` (new) | Ephemeral, community, and subscription objects and parent integration. |
| Request layer | `schema.ron`, generated `payloads/*.rs`, `payloads.rs`, `bot/api.rs` | API 10.2 method/parameter metadata and generated requests. |
| Forwarding | `local_macros.rs`, `adaptors/{cache_me,parse_mode,trace,erased}.rs`, `adaptors/throttle/requester_impl.rs` | Non-generated requester forwarding. |
| Schema/release | `custom_v2.json`, `schema_check/*`, readmes, crate docs, changelogs, migration guide | API conformance and release declaration. |
