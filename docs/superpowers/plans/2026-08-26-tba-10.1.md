## Phase 2 — RichText tree

### Task 2.1: `crates/teloxide-core/src/types/rich_text.rs`

- [ ] `RichText` enum: `Plain(String) | List(Vec<RichText>) | Formatted(Box<RichTextKind>)`
      with `#[serde(untagged)]` — box **only** here
- [ ] `RichTextKind` enum: 25 variants, `#[serde(tag = "type", rename_all = "snake_case")]`
      — no explicit `#[serde(rename)]` needed (all 25 wire strings match
      `snake_case` of the chosen variant names); verify with a tag-assertion
      test instead of manual renames
- [ ] 25 leaf structs (`RichTextBold`, `RichTextItalic`, `RichTextUnderline`,
      `RichTextStrikethrough`, `RichTextSpoiler`, `RichTextDateTime`,
      `RichTextTextMention`, `RichTextSubscript`, `RichTextSuperscript`,
      `RichTextMarked`, `RichTextCode`, `RichTextCustomEmoji`,
      `RichTextMathematicalExpression`, `RichTextUrl`,
      `RichTextEmailAddress`, `RichTextPhoneNumber`,
      `RichTextBankCardNumber`, `RichTextMention`, `RichTextHashtag`,
      `RichTextCashtag`, `RichTextBotCommand`, `RichTextAnchor`,
      `RichTextAnchorLink`, `RichTextReference`, `RichTextReferenceLink`)
      — exact fields per reference spec:
      - `text: RichText` **unboxed** on all variants that have it (i.e. all
        except `RichTextAnchor`, `RichTextMathematicalExpression`,
        `RichTextCustomEmoji`)
      - `RichTextDateTime`: `text: RichText, unix_time: i64, date_time_format: String`
        (both extra fields required)
      - `RichTextCustomEmoji`: `custom_emoji_id: String, alternative_text: String`
        (no `text` field)
      - `RichTextAnchor`: `name: String` only
      - `RichTextMathematicalExpression`: `expression: String` only
      - each with its own doc comment + `[The official docs](anchor)` link
      - derives: `Clone, Debug, Eq, Hash, PartialEq, Serialize, Deserialize`
        + `#[cfg_attr(test, derive(schemars::JsonSchema))]` on all of
        `RichText`, `RichTextKind`, and all 25 leaf structs
      - `#[serde_with::skip_serializing_none]` above the derive on any
        struct with an `Option` field (none of the leaf structs here should
        have one — flag if any reference-spec field looks optional and
        confirm against the source)
- [ ] If `clippy::large_enum_variant` fires on `RichTextKind`, box the
      offending inner field only (e.g. `RichTextTextMention.user:
      Box<User>`) — do not reintroduce a leaf-level `Box<RichText>`
- [ ] Register module in `types.rs` (both `mod`/`pub use` blocks)

### Task 2.2: Tests

- [ ] Deserialize plain string as `RichText::Plain`
- [ ] Deserialize array-of-strings as `RichText::List`
- [ ] Deserialize nested formatting: `RichTextBold` wrapping `RichTextItalic`

- [ ] Deserialize each text-less leaf (`RichTextAnchor`,
      `RichTextMathematicalExpression`, `RichTextCustomEmoji`)
- [ ] Unknown-tag rejection: `{"type":"nonexistent","text":"x"}` errors

      sufficient proof — e.g. use them as a `HashSet` key in a test)
- [ ] Table-driven test asserting all 25 wire `type` strings
      (mirror `poll_media_variants_serialize` style in `input_poll_media.rs`)
- [ ] `cargo test` green for this module

## Phase 3a — RichBlock tree + top-level rich objects (types only)

### Task 3a.1: `crates/teloxide-core/src/types/rich_block.rs`

- [ ] `RichBlock` enum: 21 variants, `#[serde(tag = "type", rename_all = "snake_case")]`
      — no explicit renames needed (all 21 wire strings match `snake_case`);
      verify with a tag-assertion test
- [ ] 3 supporting sub-objects (no `type` tag): `RichBlockCaption`,
      `RichBlockTableCell`, `RichBlockListItem`
- [ ] `CellAlign { Left, Center, Right }` and
      `CellVAlign { Top, Middle, Bottom }` enums, `#[serde(rename_all = "snake_case")]`
      — used as **required** fields `RichBlockTableCell.align: CellAlign`,
      `.valign: CellVAlign`
- [ ] `RichBlockListItem.r#type: Option<String>` with
      `#[serde(rename = "type")]` — this is a **data field** (ordered-list
      label style `"a"|"A"|"i"|"I"|"1"`, case-sensitive), **not** a
      discriminator; the schema checker's `type`-field exception means this
      will NOT be auto-caught if wrong — add an explicit deserialization
      test asserting `{"type":"a", ...}` round-trips correctly
- [ ] 21 block structs, exact fields per reference spec:
      - `RichBlockList.items: Vec<RichBlockListItem>`
      - `RichBlockListItem.blocks: Vec<RichBlock>`
      - `RichBlockBlockQuotation.blocks: Vec<RichBlock>`, `.credit: Option<RichText>`
      - `RichBlockCollage.blocks` / `RichBlockSlideshow.blocks: Vec<RichBlock>`,
        `.caption: Option<RichBlockCaption>`
      - `RichBlockDetails.blocks: Vec<RichBlock>`, `.summary: RichText` (required),
        `.is_open: bool` (received flag — skip_serializing_if, not Option)
      - `RichBlockTable.cells: Vec<Vec<RichBlockTableCell>>`,
        `.caption: Option<RichText>` — **not** `RichBlockCaption` (the one
        block that diverges from the caption-type convention — double check
        this field specifically)
      - `RichBlockMap.location: Location` (import from `crate::types::location`),
        `.zoom: i64, .width: i64, .height: i64`, `.caption: Option<RichBlockCaption>`
      - Media blocks reference existing `Animation`/`Audio`/`PhotoSize`/`Video`/`Voice`;
        `has_spoiler: bool` (received flag) on Animation/Photo/Video only
      - No `Box` needed anywhere in this file (all recursion via `Vec`)
      - Derives: `Clone, Debug, PartialEq, Serialize, Deserialize` ONLY
        (no `Eq`/`Hash`) for: `RichBlock`, `RichBlockMap`, `RichBlockListItem`,
        `RichBlockList`, `RichBlockBlockQuotation`, `RichBlockCollage`,
        `RichBlockSlideshow`, `RichBlockDetails` — poisoned transitively by
        `Location` (f64 fields)
      - Full `Clone, Debug, Eq, Hash, PartialEq, Serialize, Deserialize` for
        everything else in this file: `RichBlockCaption`, `RichBlockTableCell`,
        `CellAlign`, `CellVAlign`, `RichBlockParagraph`, `RichBlockSectionHeading`,
        `RichBlockPreformatted`, `RichBlockFooter`, `RichBlockDivider`,
        `RichBlockMathematicalExpression`, `RichBlockAnchor`,
        `RichBlockPullQuotation`, `RichBlockTable`, `RichBlockAnimation`,
        `RichBlockAudio`, `RichBlockPhoto`, `RichBlockVideo`, `RichBlockVoiceNote`,
        `RichBlockThinking`
      - `#[serde_with::skip_serializing_none]` above the derive on every
        struct with an `Option` field
      - Doc-comment + anchor-link convention on every struct (same as Phase 2)
      - `RichBlockThinking`: add a doc note that it is send-only (used only
        in `sendRichMessageDraft`, never received)
- [ ] Register module in `types.rs` (both blocks)

### Task 3a.2: `crates/teloxide-core/src/types/rich_message.rs`
